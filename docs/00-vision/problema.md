# Contexto del proyecto

## Resumen

Estamos construyendo una aplicación web para una gestoría / administración de fincas en España.

La primera dirección del producto es una herramienta rápida para consultar información operativa que hoy resulta lenta o incómoda en el programa actual.

## Idea central

El dolor principal no parece ser solo falta de funcionalidad. El problema fuerte es la fricción operativa: lentitud, filtros pobres, listados limitados y poca visibilidad de un vistazo.

La herramienta no debe replicar el mismo dolor con otra interfaz. Primero hay que entender qué tareas consumen tiempo real y qué consultas necesita hacer la usuaria sin pasar por Excel o trabajo manual.

## Problema actual

- Lentitud general en el sistema actual.
- Filtros pobres o poco útiles.
- Listados incompletos o difíciles de obtener.
- Necesidad de consultar datos frecuentes sin perder tiempo navegando.
- Trabajo manual fuera del programa actual, como Excel, correos o documentos preparados a mano.

## Estado actual

- Fase de descubrimiento inicial del problema y recopilación de requisitos.
- Hay un diseño visual inicial.
- La validación informal del diseño fue positiva, descrita como "estupendo".
- Ese diseño no debe tratarse como definitivo.
- Todavía no se ha validado completamente el flujo real de trabajo.
- Todavía no se ha definido el MVP definitivo.

## Necesidad principal

Antes de construir funcionalidades reales, hay que observar y validar cómo trabaja la usuaria:

- Qué consulta primero.
- Qué filtros usa de verdad.
- Qué listados necesita cada semana o cada mes.
- Qué datos faltan en su programa actual.
- Qué pasos le hacen perder más tiempo.
- Qué exportaciones son imprescindibles.
- Qué procesos terminan haciéndose fuera del programa actual.

## Fuera de alcance actual

- Base de datos real.

- Implementación real de Norma 43 o Norma 19.
