# Reglas para usar IA

## Principio

La IA debe ayudar a pensar, documentar y ejecutar tareas pequeñas. No debe convertir una idea vaga en código grande sin control.

## Reglas estrictas

- Trabajar en tareas pequeñas.
- Evitar vibe coding.
- No pedir "hazme toda la app".
- Pedir siempre un plan antes de editar.
- Aprobar el plan antes de ejecutar.
- Revisar el diff antes de aceptar cambios.
- Ejecutar lint, typecheck o tests cuando existan y apliquen.
- Hacer commits pequeños y con una sola intención.
- Pedir explicación del código generado.
- No aceptar código que el usuario no entienda.
- No aceptar cambios que mezclen producto, UI, datos y arquitectura sin motivo claro.

## Señales de riesgo

- La tarea toca demasiados archivos sin una razón clara.
- La IA crea abstracciones antes de que exista repetición real.
- La IA instala dependencias para resolver algo simple.
- La IA define una base de datos definitiva sin validar el flujo.
- La IA implementa reglas legales, bancarias o contables sin fuentes verificadas.
- La IA crea pantallas no pedidas.

## Cómo pedir mejor trabajo

- Definir una tarea concreta.
- Decir qué está dentro y fuera de alcance.
- Pedir un plan corto.
- Pedir que se mantenga el cambio pequeño.
- Pedir resumen de archivos modificados.
- Pedir explicación de decisiones y tradeoffs.

## Regla final

Si el usuario no entiende el cambio, el cambio no está listo.
